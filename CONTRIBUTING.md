# Contributing to Py2PDF

Thank you for your interest in contributing to Py2PDF! This document provides guidelines for contributing.

## Code of Conduct

Be respectful and inclusive in all interactions.

## Getting Started

1. Fork the repository
2. Create a feature branch: `git checkout -b feature/your-feature`
3. Make your changes
4. Commit with clear messages: `git commit -am 'Add feature'`
5. Push to the branch: `git push origin feature/your-feature`
6. Submit a pull request

## Code Style

- Follow Kotlin style guides
- Use meaningful variable and function names
- Add KDoc comments for public APIs
- Keep functions small and focused
- Avoid code duplication

## Testing

- Write unit tests for business logic
- Write instrumented tests for Android components
- Ensure all tests pass before submitting PR
- Aim for >80% code coverage

## Pull Request Process

1. Update documentation for any new features
2. Add tests for new functionality
3. Ensure all checks pass (build, tests, lint)
4. Fill out the PR template completely
5. Request review from maintainers

## Issues

- Check for duplicates before creating an issue
- Provide clear description and steps to reproduce
- Include relevant environment information
- Add screenshots/logs if applicable

## Commit Messages

Use clear, descriptive commit messages:

```
<type>(<scope>): <subject>

<body>

<footer>
```

Types: feat, fix, docs, style, refactor, test, chore

## Questions?

Feel free to reach out to maintainers for guidance.
